## 1. Règles de détection

### Éligibilité

Une série candidate n’est évaluée que si :

- `setKind === 'work'` (équivalent : `!isWarmup` après sync lot 2)
- `reps != null` et `reps >= 1`
- `priorCompletedSessionCount >= 2`

où `priorCompletedSessionCount` = nombre de workouts `status === 'completed'`, `deletedAt == null`, **distincts**, contenant ≥ 1 série work de cet `exerciseId`, **hors** le `workoutId` courant.

### Kinds

| Kind | Condition |
|---|---|
| `weight` | `weightKg` > max `weightKg` des prior work |
| `reps` | `reps` > max reps parmi prior work avec `weightKg >=` candidate |
| `e1rm` | `e1rm` non null et > max e1rm prior work |
| `volume` | `weightKg × reps × (unilateral ? 2 : 1)` > max volume prior work |

Prior = séries work non soft-deleted, hors candidate, historique chronologique.

API domaine :

```ts
detectPrKinds(candidate, priorSets, {
  priorCompletedSessionCount: number;
  unilateral?: boolean;
}): PrKind[]
```

## 2. UX

### Séance active

Après `VALIDER`, si `prKinds.length > 0` :

- Bannière discrète : `Record · charge` / `Record · reps · e1RM` / `Record · volume` (libellés FR courts)
- **Une bannière par exercice** : nouvelle série PR → union des kinds affichés, pas d’empilement
- Disparaît au changement d’exercice ou à l’avance après repos
- Pas de toast plein écran ; haptic VALIDER inchangé

### Liste des séries

Retirer le suffixe `· Record` sur chaque ligne dans `SetInput` (la bannière suffit).

### Historique

Conserver un libellé discret `· Record` (+ kinds optionnels) sur les séries encore `isPR` après migration.

### Sous seuil (séances 1–2)

Aucun PR écrit, aucune bannière, pas de message « baseline ».

## 3. Écriture et édition

- `logSet` : calcule `priorCompletedSessionCount`, appelle `detectPrKinds`, persiste `isPR` / `prKinds`
- `editSetLog` : recalcule la série éditée, puis **rejoue** chronologiquement les séries work postérieures du même exercice (RG-12)

## 4. Migration

`migratePrV2()` au démarrage, setting `prRulesMigratedV2` :

1. Pour chaque exercice, ordonner les séries work chronologiquement
2. Recalculer kinds avec seuil v2 vs priors uniquement
3. Écrire `isPR` / `prKinds`
4. Idempotente

## 5. Critères d’acceptation

1. 0–1 séance completed antérieure → aucun PR.
2. ≥ 2 séances antérieures + charge > max → kind `weight` + bannière.
3. Warmup / approach → jamais PR.
4. Deux séries PR dans le même exercice → une bannière, kinds fusionnés.
5. Migration one-shot ; 2ᵉ run no-op.
6. Édition qui annule un max → flags de la série et des suivantes cohérents.
7. Tests domaine + repo verts.
